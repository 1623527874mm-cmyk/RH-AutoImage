# RH 定时生图（RH-AutoImage）· SillyTavern 扩展

按 **AI 回复楼层** 计数，每 N 条 AI 回复，把触发的那条回复交给 DeepSeek 生成**正向**提示词，
负面词用你自己填的固定值（不经过模型），再调用 **RunningHub AI 应用** 生图，
最后把图片挂回**触发的那一层楼**。

全程异步，不阻塞聊天；不依赖酒馆原生生图功能，也不依赖正则。

**装完三步就能用**：① 填两个 Key（DeepSeek + RunningHub）→ ② 勾选「启用插件」→ ③ 正常聊天。
应用 ID、正负节点映射、正向模板、固定负面词都已经作为**公开默认配置**随仓库发布，开箱即用；
这些默认值全部是你可改的普通文本，不含任何凭证。

> ⚠️ 装完**默认是关闭状态**（`enabled = false`）。关闭时插件**不会自动触发生图**——
> 聊天、收发消息都不会发起任何 DeepSeek / RunningHub 请求，也不会消耗任何额度。
>
> 但**两个手动测试按钮与开关无关**：即使插件处于关闭状态，点「测试 DeepSeek」仍会真实请求一次模型（消耗少量 token），
> 点「测试 RunningHub 应用」仍会**真实提交一次任务并产生真实费用**。不点就不会有这些消耗。
>
> 默认 `interval = 1`，即启用后**每条 AI 回复都触发一次生图**；想省钱先把它改成 3 或更大，再启用。

## 1. 兼容性

| 项目 | 值 | 依据 |
|---|---|---|
| 已核实基线 | **SillyTavern 1.18.0** | 在该版本上实际加载并跑通整套流程，并逐一核对了本扩展用到的 4 个公开模块导出 |
| 最低声明版本 | `1.18.0`（`manifest.minimum_client_version`） | 低于此版本不声明兼容，酒馆会跳过加载 |
| 服务端插件 | 不需要（`enableServerPlugins: false` 也能用） | 全部逻辑在前端，只走 `fetch` |
| 其它版本 | **未验证** | 不声称兼容 |

本扩展依赖的公开接口（均在 1.18.0 中确认存在）：

| 导入 | 来源 | 用途 |
|---|---|---|
| `eventSource` / `event_types` | `/script.js` | 监听生成事件 |
| `saveChatConditional` / `updateMessageBlock` / `saveSettingsDebounced` | `/script.js` | 存盘 / 重绘 / 存设置 |
| `extension_settings` / `getContext` | `/scripts/extensions.js` | 设置与聊天上下文 |
| `MEDIA_TYPE` / `MEDIA_SOURCE` | `/scripts/constants.js` | 酒馆原生媒体结构 |
| `saveBase64AsFile` | `/scripts/utils.js` | 图片写入酒馆图片目录 |

入口由酒馆以 `<script type="module">` 加载，因此 `index.js` 用 ES module 语法、相对路径引 `./lib/*.js`。
扩展**不读**服务器绝对路径、不依赖容器目录、不引用任何服务器私有文件。

## 2. 安装

三种方式任选其一，都不需要重启容器，装完**强制刷新**浏览器（Ctrl/Cmd+Shift+R）。

### 方式 A：扩展管理器（推荐）

酒馆「扩展」页 → *Install Extension* → 填本仓库的 Git 地址 → 安装后刷新。
酒馆会自动把扩展放进 `data/<user-handle>/extensions/<仓库名>/`。

### 方式 B：手动放目录

把整个目录（不要包含 `test/`、`node_modules/`）复制到：

```
<SillyTavern 数据目录>/<user-handle>/extensions/RH-AutoImage/
```

Docker 部署时，`<数据目录>` 就是挂载进容器的那个卷，宿主机路径因人而异。
目录内必须能直接看到 `manifest.json`（不能多套一层同名文件夹）。

### 方式 C：压缩包

把目录打成 zip，解压到上面同一位置，确保 `manifest.json` 在扩展目录根部。

### 装完之后（三步）

1. 酒馆「扩展」面板打开 **RH 定时生图** 抽屉，填 **DeepSeek API Key** 与 **RunningHub API Key**；
2. **勾选「启用插件」** —— 不勾不会出图（默认 `enabled = false`）；
3. 正常聊天，每 `interval` 条 AI 回复自动出一张图（默认 `interval = 1`，即每条都出，介意花费就先调大）。

> 设置抽屉顶部的状态行会直接告诉你还缺什么，缺项时不会发出任何请求。

### 升级

方式 A 用扩展管理器自带的更新按钮；方式 B/C 覆盖目录内容后强制刷新。
设置存在 `extension_settings.rh_autoimage` 里，**覆盖文件不会丢配置**。
旧版 `positivePrefix` / `negativePrefix` 会在升级后以只读形式显示在设置面板，需你手动处理（不自动拼接）。

### 卸载

删除扩展目录 → 强制刷新。插件不会再执行任何逻辑。
可选清理：酒馆设置里的 `extension_settings.rh_autoimage` 会残留一份配置（含你填的 Key），
需要彻底清除时在「扩展设置」里手动删除该键，或直接编辑设置文件。已生成的图片不受影响。

## 3. 配置

安装后在酒馆「扩展」面板找到 **RH 定时生图** 抽屉。

### 3.1 你需要填的（只有两个 Key）

**填上这两个 Key 就能用**，其余全部自带默认值：

| 配置项 | 默认值 | 你要做什么 |
|---|---|---|
| DeepSeek API Key | 空 | 填你自己的 |
| RunningHub API Key | 空 | 填你自己的 |

> 🔑 两个 Key 都默认空，源码、测试、README、日志里都不存在任何真实 Key。
> 插件不会读、不会上传、不会记录你的 Key；它们只存在本机 `extension_settings` 里。

#### 填完 Key 之后还有一步：勾选「启用插件」

**插件默认不启用。** 填完 Key 只是让它「有能力」出图，真正开始工作需要手动打开总开关：

1. 在同一个设置抽屉顶部勾选 **启用插件**；
2. 想确认通不通，先点 **测试 DeepSeek**（真实请求一次模型，消耗少量 token）；
3. **测试 RunningHub** 会**真实提交一次任务、产生真实费用**，确认要继续再点；
4. `interval`（默认 **1**）决定出图频率 —— **默认每条 AI 回复都出图**，
   不想这么频繁就先改成 3 或更大，再勾启用。

> 关掉「启用插件」后：**不会再自动启动新任务**，聊天不会再触发生图。
> 注意两点：
> - 这个开关只控制「自动触发生图」，**管不住两个手动测试按钮**——它们在关闭状态下照样会发请求；
> - **已经提交出去的任务不会因为这个开关而停止**：RunningHub 那边的费用在提交那一刻就已经产生，
>   关掉开关既不会退回也不会中断它，任务会继续跑到结束（结果仍会挂回原楼层）。
>   要避免这种情况，请在关掉开关前先确认没有正在跑的任务。
>
> 这两个默认值（`enabled = false`、`interval = 1`）是刻意定的，不会被自动改动。

其余项都有可用默认值，想改再改：

| 配置项 | 说明 |
|---|---|
| DeepSeek API 地址 / 模型名 | 默认 `https://api.deepseek.com`、`deepseek-chat` |
| 正向关键词生成模板 | 原样发给 DeepSeek。默认含质量词、男主 POV、「一图一秒」规则，可直接改 |
| RunningHub 应用 ID | 默认本项目应用；换成你自己的时直接改，插件不覆盖 |
| 正面 / 负面节点 ID 与字段名 | 默认对齐本项目应用（见 3.3） |

### 3.2 关于默认应用 ID

默认值 `2116435600285958146` 只是**本项目当前使用的应用**，方便本机开发时少填一个框：

- 它**不是凭证**，也不保证其他账号可访问；
- 你必须有权限运行这个应用（或用你自己的应用替换）——RunningHub 的应用归属与配额由账号决定，
  本项目不保证任意账号都能跑它；
- 换成你自己的应用时直接改这一栏，插件**不会**覆盖你填的值；
- 已作废的旧 ID `2116336611532275714` 命中时只弹一次提醒，不改你的设置。

### 3.3 节点 ID 与字段名怎么填（最容易错的地方）

RunningHub 的 AI 应用里，每个输入都是一个节点，节点有 `nodeId` 和 `fieldName`。
插件只往你指定的节点写值，**不猜、不覆盖**。

怎么查：在 RunningHub 打开该应用 → 工作流编辑界面 → 点开接收提示词的节点
→ 记下节点 ID 与输入字段名（例如 `1195` / `text`）。

| 项 | 默认值（本项目应用） | 说明 |
|---|---|---|
| 正面节点 ID | `1195` | 换了应用就跟着改 |
| 正面字段名 | `text` | 换了应用就跟着改 |
| 负面节点 ID | `1018` | 应用无负面输入就留空，留空则不提交该节点 |
| 负面字段名 | `text` | 同上 |

> ⚠️ **字段名 `prompt` vs `text`**
> 本项目所用应用记录中的字段名是 **`text`**，默认值已经对齐它。
> 但 `prompt` 是很多工作流的常见字段名 —— 换成你自己的应用时，请以工作流里实际的字段名为准。
> 填错的典型报错是 `NODE_INFO_MISMATCH`，而且提交已经发生（可能计费）。
> 若你把正面字段名改成 `prompt` 却仍用默认应用，状态栏会给出一条软提示（只提醒，不改你的值）。

> ⚠️ **升级用户注意**：默认值只补「从未保存过」的字段。
> 你已经在设置里存过的值（包括刻意留空）**一律不覆盖**，唯一的例外是 `rhAppId` 为空串时会补上当前默认应用 ID。

### 3.4 其余配置项

| 配置项 | 说明 |
|---|---|
| 启用插件 | **默认关闭**（`enabled = false`）：关闭时不会自动触发生图，聊天不会消耗额度。关闭后不再启动新任务，**但已在跑的任务不会因此中断**（提交时已计费）。**手动测试按钮也不受此开关控制**（见下方说明） |
| 每 N 条 AI 回复生成一次 | 默认 **1**（`interval = 1`，每条 AI 回复都触发）；正整数，N=3 表示第 3、6、9… 条；用户消息不计 |
| 角色人设关键词 | 多行，**由你手动维护**，插件不读角色卡；**默认留空**，示例见 3.5，复制粘贴即可 |
| 正向关键词生成模板 | 默认已带；决定 DeepSeek 怎么把「人设 + 正文」压成一条正向提示词 |
| 固定负面关键词 | 默认已带一套通用质量负面词；**不发给 DeepSeek**，原样填入负面节点；留空则不提交 |
| 附加节点 JSON | 该应用其它必填参数，如 `[{"nodeId":"145","fieldName":"value","fieldValue":"5"}]` |
| 轮询间隔 / 最长等待 | 默认 5s / 600s（强制下限 2s / 60s） |
| 单请求超时 | 默认 60s |
| 最大并行任务数 | 默认 5，超出则该楼层标记跳过，避免并发爆炸和重复计费 |

两个测试按钮（**与「启用插件」开关无关，关闭状态下点击依然会发请求**）：

| 按钮 | 行为 | 费用 |
|---|---|---|
| 测试 DeepSeek | 真实请求一次模型，用一段固定示例正文跑一次正向词生成 | 消耗少量 token（按你的 DeepSeek 单价计） |
| 测试 RunningHub 应用 | **真实提交一次任务**到 RunningHub，返回 taskId | **产生真实费用**，按你账号的算力/应用计费 |

两个按钮都会先检查自己需要的字段（Key、应用 ID、正面节点与字段名），缺字段时只提示、不发请求。
但只要字段齐全，**点一下就是一次真实调用**——不想花钱就别点。

### 3.6 请求体契约（不改工作流其它参数）

提交体只有三部分：

```json
{
  "nodeInfoList": [{ "nodeId": "…", "fieldName": "…", "fieldValue": "…" }],
  "instanceType": "default",
  "usePersonalQueue": "false"
}
```

- **不发送** `width` / `height` / `resolution` / `size` / `aspectRatio`；
- 输出分辨率完全由你的应用工作流决定（本项目应用为 4:3 / 1280×960）；
- 换应用后分辨率随应用走，插件无需改动。

## 4. 行为与边界

- **计数**：只数 AI 回复（`is_user` / `is_system` 均不计）；每次按当前聊天现存顺序重算，
  删除消息后计数自动校正，不会因内存计数器漂移。
- **只总结触发的那一条回复**：不合并前后楼层、不发角色卡/世界书。
- **去重**：去重标记只存在**扩展运行时内存**里；同一楼层（同一正文）已排队/已完成就不会二次提交。
  刷新页面后这些标记会消失，但聊天本身不会因此重新触发（触发只发生在新的生成事件上）。
- **不补图**：打开/切换聊天只建立计数，不给历史楼层补生成；编辑消息不触发。
- **异步**：任务在后台跑，聊天可以继续。
- **不跨聊天写回**：任务启动时记下「目标聊天标识 + 楼层 + 正文哈希」。切走聊天后该任务立即作废，
  结果**直接丢弃**；插件从不调用 `/api/chats/save` 之类的全量写接口去后台改别的聊天。
- **写回前四重复核**：是不是同一个聊天 / 同一楼层 / 原文没变 / 楼层还是 AI 消息。
  任一条不满足就丢弃结果 —— 楼层被删、被编辑、或前面楼层被删导致索引漂移，都不会把图挂到相邻楼层。
  异步下载完成后、真正挂图之前**再校验一次**（下载是最慢的一步，窗口最长）。
- **删除**：目标楼层被删 → 取消在跑的任务（能取消则取消，不能取消则丢弃结果）。
- **任务状态不落盘**：status / taskId / error / 去重标记只存在内存 Map 里，**不写 `message.extra`、不进聊天 JSONL**。
  刷新后运行中的状态角标会消失（预期行为），已生成的图片不受影响。
- **图片持久化**（唯一允许写进消息的东西，且用的是酒馆原生结构）：
  下载 RunningHub 结果 → base64 走 `saveBase64AsFile()`（`POST /api/images/upload`）存进酒馆图片目录
  → 以 `extra.media[]` + `media_index` + `inline_image` 挂到该楼层 → `updateMessageBlock()` 重绘
  → `saveChatConditional()` 交给酒馆自己存盘。
  因此图片**刷新后仍在**、能随聊天导出，且不依赖 RunningHub 24h 时效链接。
- **失败隔离**：单楼层失败只在该楼层显示错误，不影响聊天和其它楼层。
- **失败绝不半成品**：任何一步失败都不挂空图片、不保存聊天、不自动重试。
  已下载/已挂上的图片数保持原样，任务在内存里标成 `failed` 并带一条脱敏原因。

### 4.1 RunningHub 失败路径（P3）

| 情况 | 处理 | 用户看到 |
|------|------|----------|
| HTTP 非 2xx | 抛错，只带状态码 + 脱敏原因 | `RunningHub 提交失败（HTTP 500）：…` |
| 响应体不是 JSON（网关 HTML 页） | 不当成成功，也不回显页面 | `RunningHub 提交返回非 JSON（HTTP 502）` |
| `code` / `errorCode` 非 0 | 业务拒单 | `提交被拒绝：<原因>` |
| `success: false` | 业务拒单 | 同上 |
| `errorMessage` / `failedReason` | 作为原因，先脱敏再截 200 字 | 混在上面两种里 |
| 成功但无 `taskId` | 立刻失败，不进轮询 | `未返回 taskId，无法继续查询` |
| 状态 `FAILED` | 即使 HTTP 200 + `code:0` 也算失败 | `RunningHub 任务失败：<原因>` |
| 轮询超时 | 到点即放弃，带最后状态 | `轮询超时（最后状态 RUNNING）…` |
| 成功但结果里没有图片 | 明确报「没有图片」 | `任务成功但没有图片结果（返回类型：txt）` |
| 下载非 2xx / 0 字节 | 抛错，第一张失败即中止，不再打无用请求 | `下载图片失败（HTTP 403）` / `下载到的图片为空` |

脱敏字典在每一层都带：`rhApiKey`、`deepseekApiKey`、人设、模板、固定负面词、当次正向词、
回复正文、提交体里每个节点的 `fieldValue`，外加 `Bearer xxx` / `sk-…` / `rh-…` 正则兜底。
`normalizeRhResponse()` 返回的对象**不保留 `raw`**，从根上避免整包响应被日志打出去。

## 5. 安全

- 所有 Key 走 `type=password` 输入框，只存在本机 `extension_settings`（不回传服务器）。
- 日志与错误信息统一脱敏：抹掉 Key 原文、`Bearer xxx`、`sk-…`、`rh-…`，
  以及人设 / 模板 / 正向词 / 负面词 / 回复正文（服务端错误常把这些回显出来）。
- 不把提示词或错误写进聊天正文：楼层状态角标是纯 DOM，聊天记录里只多出图片本身。
  **不保存正向提示词、人设、模板与正文原文**（任务结束即随内存释放）。
- 人设、模板、正文、提示词结果、API Key 均不写日志。
- 输入过长时**拒绝本次调用**（不静默截断），提示里只有字段名/长度/上限，不含原文。
- 网络请求全部带超时；轮询有上限；不使用关闭浏览器安全策略的手段。
- **不收集、不硬编码任何真实 Key**；源码中不存在任何 Key 字符串。
- 应用 ID 有默认值，但**只是默认值**：你填的值永远优先，插件不会覆盖；命中已作废的应用 ID 只弹一次提醒。

## 6. 已知限制

1. **跨域**：在开发机上（SillyTavern 1.18.0 + 现代 Chromium）实测 `api.deepseek.com` 与
   `www.runninghub.ai` 的 CORS 预检通过，浏览器可直连，**不需要后端代理**。
   该结论只对已验证的环境成立；若你换自建反代导致 CORS 失败，
   请在该反代上加 `Access-Control-Allow-Origin`，不要用 `--disable-web-security`。
2. **不跨聊天写回**：切走聊天后该任务的结果直接丢弃，不在后台写任何存档。
   代价是「切走后回来」拿不到那张图 —— 这是为了绝不覆盖别的聊天存档而做的取舍。
3. **v1 只支持单人聊天。** 群聊里自动不触发：`group-chats.js` 会在调用 `Generate()` **之前**
   把 `regenerate` 归一成 `'normal'`（`const generateType = ['swipe','impersonate','quiet','continue'].includes(type) ? type : 'normal'`），
   于是 `GENERATION_STARTED` 收到的也是 `'normal'`，意图闸无法区分「重新生成」和「普通生成」。
   因此用 `getContext().groupId`（即 `selected_group`）这个可靠标识直接跳过群聊，不做启发式猜测。
4. 图片保存目录随酒馆设置（`user/images/<角色名>/`），删聊天不会自动删图；需要清理时按目录手动删。
5. 不做「编辑消息后重生成」，也不做「历史补生成」——这不是本扩展的目标范围。
6. **分辨率由 RunningHub 工作流决定**（本项目所用应用为 4:3 / 1280×960）。插件**不传** width / height / resolution / size，
   也不写死、不覆盖；提交体只有 `nodeInfoList` + `instanceType: 'default'` + `usePersonalQueue: 'false'`。
   换应用后分辨率会跟着应用走，插件无需改动。
7. **旧版设置迁移**：`positivePrefix` / `negativePrefix` 的原文会搬到设置面板里可见的
   「旧版前缀（已保留，未生效）」区域，不自动拼入任何提示词；确认后点「已处理，清除旧值」删除。
   为什么不全自动迁移：旧语义是「插件本地硬拼的前缀」，新语义是「模板 + 固定负面词」，
   无法无损对应，插件不猜。

## 7. 开发与测试

```bash
npm test     # 等价：node --test test/core.test.js test/api.test.js test/events.test.js \
             #             test/settings.test.js test/jobs.test.js test/errors.test.js \
             #             test/regression.test.js
```

- 共 **228 项**，全部离线：假 `fetch` + 假图片保存，不触网、不调用真实 DeepSeek / RunningHub
- 无需安装任何依赖（`package.json` 无 `dependencies`，只用 Node 内置 `node:test`）
- Node 版本：测试在 Node 22 上跑通；扩展本身在浏览器里运行，与 Node 版本无关
- 语法检查：`node --check index.js && node --check lib/*.js && node --check test/*.js`

- `lib/core.js`：纯逻辑（计数 / 触发 / 正文指纹 / 解析 / 状态归一化 / 结果筛选 / 载荷构造），无酒馆依赖。
- `lib/api.js`：网络层（DeepSeek + RunningHub + 轮询 + 下载），可注入假 fetch 做测试。
- `lib/jobs.js`：任务运行时状态（内存 Map）+ 写回安全判定（`planAttach`）+ 任务主流程（依赖注入，可离线跑全链路）。
- `lib/settings.js`：设置默认值与旧版迁移的唯一入口。
- `lib/trigger.js`：触发控制器（生成意图闸 + 预备/放行配对）。
- `test/errors.test.js`：P3 失败路径矩阵（HTTP 码 / 非 JSON / 业务码 / 失败状态 / 超时 / 无图 / 下载失败 / 脱敏 / 不 attach 不 save）。
- `test/regression.test.js`：删楼后的触发回归（N=1 / N=3 重算、重复渲染不重复触发、regenerate·swipe·continue 不触发）。
- `index.js`：酒馆集成（事件绑定、设置 UI、DOM 读正文、图片保存与重绘）。
